# CDKA Proof Engine v5 — Changing the organization instead of only improving precision

**Status:** executed finite-family proofs, exact code and adversarial examples; no general original CDKA theorem established. This increment addresses v4's structural, dependence and recovery hypotheses while keeping information, physical implementation and resources separate.

## Strategic distinction

The cost of indefinitely accurate operation in a fixed fatal-error architecture is not automatically the cost of maintaining an adaptive organization. Distinguish reducing component errors, making faults nonfatal by correction, and paying to install a qualitatively different policy family.

The aim is one implementable policy that survives until installation is funded, copies its actual physical knowledge into the new mechanism, and maintains it under a declared disturbance model. A better controller is not assumed available at time zero.

## Backward proof chain

1. Declare the guarantee: mean lifetime, high finite-horizon probability, positive infinite survival and sure safety are distinct.
2. Declare all readable memory, resource, clocks, selectors, decoders and persistent seeds.
3. Identify a task-compatible non-killing support under a common implementable controller.
4. Compute reachability of that support; do not confuse reachability with initial membership.
5. Price reconfiguration, risk, downtime and survival while saving resources.
6. Specify joint noise and the logical failure event rather than only local marginals.
7. Prove attainment, compare independent finite oracles, and attack with support/correlation/switching changes.
8. Audit against coding, resource-constrained MDPs, finite-state POMDPs and switched-system theory before originality claims.

## Executed results

| Result | Instrument | What can falsify an overgeneralization |
|---|---|---|
| XOR failure a+b-2t and sharp coupling interval | Frechet polytope, parity algebra | Same marginals can cancel or aggravate task error |
| Three-bit correction changes safe support under bounded upsets | Hamming distance and support invariant | Multiple upsets/noisy corrector restore fatal transitions |
| Infinite survival of a fixed complete controller equals safe-support hitting | Positive kernels, exact linear systems | Hidden-state oracle or omitted clock is invalid |
| Recovery raises mean life to order 1/d^2 without a safe class | Resolvent and spectral radius | Correlated simultaneous damage removes the gain |
| Individually dying modes compose into a safe alternating loop | Noncommuting matrix products | Mode-by-mode spectral inspection is insufficient |
| Financed finite-horizon installation policy | Bellman optimal stopping and resource dynamics | Context-dependent resource signaling changes the library |
| Indefinite upgrade value is a DAG recursion | Resource monotonicity and removal of nonprogress steps | Positive upgraded error still kills infinite survival |
| Negative-log success becomes a min-plus path problem | Product-to-sum algebra | Negative log failure is not negative log success |

## Analysis tools separated by function

**Algebra/couplings:** joint probability tables; XOR/majority polynomials; error balls and code distance; products of sub-stochastic matrices; support closure.

**Linear/spectral:** rational Gaussian elimination; (I-Q)^(-1) lifetime; spectral-radius decay; SCC algorithms. A fixed full-controller result cannot be applied automatically to arbitrary switching of hardware modes.

**Optimization:** finite-resource Bellman recursion; independent exhaustive path/prescription enumeration; shortest paths only after a proved monotonic reduction; explicit finite-to-infinite error certificates.

**Calculus/asymptotics:** distinguish 1/d from 1/d^2 lifetime; failure action versus log success; noncommuting zero-noise/infinite-horizon limits; capacity thresholds versus smooth finite-time performance.

**Physical calibration:** next derive the correction/rewriting errors from the same causal endpoints, deadlines and interventions, and charge for the corrector, acquisition and storage. Correlation must be measured or bounded. A perfect corrector is a model boundary, not a derived physical fact.

## Next prioritized proof obligations

**R5.1 — Remove the ideal corrector.** Include correction faults and upkeep in the complete kernel. Determine whether the purported protected class is closed or only metastable. A code protecting data with an unmodeled perfect decoder has not explained constitutive autonomy.

**R5.2 — Minimum installation cost of a knowledge-compatible recurrent component.** Let structure-changing actions alter observation classes and Phi(Z,R). Derive a policy-consistent resource/authority certificate for reaching and maintaining a task-compatible recurrent component. Compare directly to consumption POMDPs and partial-observation energy games.

**R5.3 — Changing world.** A perfectly stored static bit is not updated knowledge of an evolving environment. Add costly acquisition and state transitions and distinguish preservation of useful distinctions from preservation of obsolete information.

**R5.4 — Composition rather than renaming.** Seek a certificate combining task-compatible support, physical policy implementability and resource-causal recurrent upkeep. It must add value beyond solving a standard large POMDP under new terminology. Candidate instruments: abstraction error bounds, repair-sufficient information states, compositional invariants and exact lower-bound duals.

## Boundary on claims

All mathematical building blocks have strong antecedents. This increment provides explicit synthesis, sharp scoped examples and falsified simplifications, not a priority claim or an explanation of spontaneous goal formation. The next originality gate is a theorem about coupled, endogenously maintained information architectures that survives these counterexamples.
